# 图片上传与展示（2026-09-22）

## 当前链路

选图请求原文件 → 本地读取大小、文件头和尺寸 → 云函数确认主人身份并签发指定路径凭据 → wx.uploadFile 直传二进制文件 → 云函数下载核对实际大小与文件头 → 自动保存草稿 → 主人更新展示。

新照片和视频封面不再调用 preparePhotoUpload/uploadPhoto，不编码 Base64，也不调用 wx.compressImage。不自动降分辨率或质量。保留的是微信选择器返回的原文件，不能承诺操作系统不会在选图时进行格式转换。

应用支持 JPG、PNG、WebP，单文件最多 30 MiB（31,457,280 字节）。这是直传与校验的资源上限，超限明确提示，不悄悄压小。HEIC/GIF/TIFF 等暂不自动转换，需导出兼容格式。手机相册原文件不修改，原文件内已有的元数据也不自动清除。

## 展示和压缩

- original/url：持久 File ID，指向上传的未加工文件；点击大图读取原文件，不添加图片处理参数。
- thumbnail：继续保存 File ID；展示时动态派生，不把临时链接写入数据库，不额外维护缩略图文件。
- 正常展示：imageMogr2/thumbnail/1080x1080/format/webp/quality/85。有损压缩仅作用于可重新生成的展示副本。
- WebP 加载失败：转 1080px PNG 缩略图，保留透明度；处理服务仍不可用再读原文件。每级只尝试一次，最终失败保留原有重试入口；原文件回退会增加下载量。
- 首次图片使用原生 lazy-load；替换已经显示的图继续 A/B 预加载，成功后切换，失败保留旧图。晚到的旧 URL 事件不推进新图状态。
- 处理规则集中在 miniprogram/config/image.ts；File ID 解析、变体缓存与批量预热在 services/cloud-file-url.ts，兼容 photo-url 原有导出。

## 上传与恢复边界

- 新服务：miniprogram/services/image-upload.ts。只读取元数据与 16 字节头到 JS，不将整张图片转成字符串。
- 新云端模块：cloudfunctions/weddingApi/image-upload.js；photos.js 必须先以真实 getWXContext().OPENID 验证 ADMIN_OPENIDS，再调用模块。
- 新 action：prepareImageUpload / verifyImageUpload；payload 为 requestId、size、format。签发路径由服务端按真实身份与请求编号哈希生成，客户端不能任意指定目录。
- 同一条目重试复用路径；已收到上传成功响应就保存 fileID，校验失败只重试校验；草稿保存失败只重试保存。
- 本机恢复队列新增可选 imageUpload/coverUpload 状态，不更换 storage key，不改数据库形状。旧版已上传记录按原方式复用。
- 图片及封面上传现在同样支持进度和 abort。页面隐藏暂停队列；已发出的校验请求不能撤回，完成结果仍记录，取消后不推进草稿。
- 服务端校验是大小与格式文件头核对，不是完整图片解码或内容审核。校验需读取完整文件，产生云存储读取流量；仅授权管理员能够调用。
- 结果不确定的文件不自动删除。失败文件可复制 File ID 后经原有引用检查清理，WebP 已纳入受管理扩展名。

## 兼容与迁移

保留旧 uploadPhoto 云函数接口和标记 deprecated 的 photo-upload.ts，只用于历史兼容及旧测试；新链路不会在直传失败时退回 Base64。应先部署兼容新旧接口的云函数，再上传新版小程序。

不迁移、不删除旧照片；原 Photo、imageUrl、旧存储队列、草稿/发布分离及页面入口继续兼容。以前被压小的文件无法无损恢复，需要重新上传真正的原图并替换展示安排。旧选择队列里的图片也可能已被旧版选择器压缩，建议重新选择。

## 部署顺序

1. 微信开发者工具中右键 cloudfunctions/weddingApi → 上传并部署：云端安装依赖。先部署云函数，再发布小程序。保留 ADMIN_OPENIDS、现有环境配置与数据库/存储权限。
2. 保持仓库锁定的 @cloudbase/node-sdk 2.10.0：已核对本机依赖使用 multipart POST 凭据。不要在本次部署中顺手跨主版本升级签发 SDK。
3. 微信公众平台 → 开发管理 → 开发设置 → 服务器域名：确认 prepareImageUpload 返回 URL 的 HTTPS 主机已加入 uploadFile 合法域名。当前环境经调试确认使用 COS 存储主机；配置时只填写主机名，不带 `https://`、路径或签名参数。保存后在开发者工具「详情 → 域名信息」刷新并重新编译，核对 uploadFile 列表。不要复制或公开完整上传 URL、凭据；视频上传主机仍需按实际环境核对。
4. 确认实际云存储临时 URL 支持 imageMogr2 缩放、WebP/PNG 输出。检查响应 Content-Type、尺寸和体积；这依赖实际环境的图片处理配置。没有开通或不可用时能回退原文件，但不等于已获得 WebP 节流收益。
5. 保留云函数足够超时与内存，现有文档建议至少 60 秒、256 MB；新照片校验也会下载最多 30 MiB，需要按实际环境验证。原图存储与点击大图流量比旧 135 KB 副本增加，缩略图不影响原文件质量。
6. 上传新版小程序体验版，在 iPhone/Android、管理员/普通访客账号完成下方验收，再按原流程发布。不需要迁移集合或开放所有用户写权限。

## 验收

本地自动测试覆盖原文件路径、不调用压缩/Base64、格式/大小限制、非管理员拒绝、稳定路径、取消与进度、校验失败恢复、封面直传、旧记录兼容、变体回退与旧事件淘汰；保留原有登记、祝福、流程、相册及音乐回归。浏览器新增真实 WebP 解码及 PNG/原文件回退测试（使用本机生成的测试图片与拦截响应，不连接云端）。

真机先取 2–3 张样片（高细节婚纱照、透明 PNG、手机横/竖图）验证，再进行批量上传：

- 原选择文件与云端下载文件字节数/哈希一致；不以肉眼或 File ID 相同代替完整性核验。
- 列表请求的是 WebP 缩略图，点击大图请求原文件；方向、颜色、透明度和比例正常。WebP 失败能回退，不无限请求。
- 多图选择、单项失败重试、上传中切后台、校验失败重进、草稿失败重试；已有成功文件不重复传输。
- 保存草稿不影响亲友，发布才更新；图片与视频封面旧数据均可显示；管理员/访客隔离及删除引用保护。
- 图片格式/体积上限、旧临时文件失效、断网和超时提示；开启合法域名校验后仍能工作。

未执行真实云端部署、存储规则修改或原图批量迁移；本地结果不能替代上述验收。
