# 小家：数据模型、记账规则与功能编号

最初的改造方案（2026-10-20，交给 Codex 的 v2）在 git 历史里；这里只留仍然有效的部分。现状和开发方式见 [README](../README.md)，接下来做什么见 [ROADMAP](ROADMAP.md)。

## 数据模型

所有集合禁止客户端直接读写，只通过云函数 `api`。每条业务记录都带 `householdId`、`ts`（创建时间戳）、`by`（记录人 openid）。

| 集合                  | 字段                                                                                 | 说明                                                                                                                                                                                                                                                                                                                                                                                                           |
| --------------------- | ------------------------------------------------------------------------------------ | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| households            | members[{openid, role, name}], memberCount, inviteCode, currency, splitting, archive | role 为 a（创建者）或 b，最多 2 人；currency 为 CNY；splitting 为「两人分摊与结算」开关，默认关；budgets 为分类预算 {分类: 每月上限（分）}；archive 为 `wedding-2026` 时可看答谢宴归档；departed 为退出过的人 [{openid, role, name, to（新小家 id）, copy, at}]；copy 为退出的人新小家里还在复制的副本进度；成员清空（members 为空）的小家是只剩一人时退出留下的，会员订单还挂在上面。旧记录里的 city 不再使用 |
| expenses              | amount, note, cat, date, payer, split, ratio, flow, src, editedBy, editedAt          | amount 单位为分；split 为 half、self、other、ratio；ratio 为 0–100 的整数，只在 split 为 ratio 时有值；flow 为 out / in；src 为截图导入的原始字段                                                                                                                                                                                                                                                              |
| todos                 | text, kind, who, done, doneOn                                                        | kind 为 shop、todo、chore（界面只分购物和待办，chore 显示在待办里）；who 为 a、b、both；doneOn 为勾完那天（1.7.0 起，旧记录没有）                                                                                                                                                                                                                                                                              |

## AI 功能

- 所有 AI 调用都走 `cloudfunctions/api/ai.js`：每个功能登记一次（档位、模型、温度、最长输出），键和 `shared/contract.json` 的 `ai` 一一对应。
- 两档：`organize`「AI 整理」（截图识别这类，结果要用户确认才保存）；`write`「AI 写文字」（喵喵小结这类，界面标「AI 生成 · 仅供参考」）。环境变量 `AI_WRITE_OFF=1` 关掉所有 `write`。
- 顺序固定：`ai.ensure(功能)`（总开关、全站费用上限）→ `quota.takeQuota`（小家的次数，先占后调，失败也算）→ `ai.read / ai.write`。
- 次数：`contract.json` 的 `ai.<功能>` 写 `free`、`vip`、`per`（day / month）；计数存在 `households.<功能>Quota`（截图和小结沿用 `billQuota`、`summaryQuota`）。
- 全站费用：每次调用按 `ai.js` 的估算单价记进 `ai_usage`；当天到 `AI_DAILY_BUDGET`（默认 20 元）的 80% 停 `write`、100% 停 `organize`。
- 发给模型的只有这个功能需要的文字，不发名字和 openid；日志只记功能名、模型、耗时、token 数和错误码。
- 提示词都在 `cloudfunctions/api/prompts.js`：用户写的内容放在分隔线里、一律当数据；要求只回 JSON 的功能由 `assist.js` / `bill-parse.js` 校验后再返回，模型说了什么都不直接信。
- 清单、吃啥、纪念日三项在 `assist.js`：`todo.split`（organize，只返回拆分结果，由用户勾选后用 `todo.add` 保存）、`dish.pick`（write，模型只回编号，按编号找回菜单里的菜，挑不在菜单里的丢掉）、`date.wish`（write，不保存，不发名字，只发纪念日名称、周年数和预算档）。模型用 `ASSIST_MODEL`，没填依次用 `SUMMARY_MODEL`、`BILL_MODEL`。
- 第一次用文字类功能弹说明（本机存 `aiTextNoticed`），写文字的结果旁一律标「AI 生成」。
- 「先确认再保存」的列表是组件 `components/draft-list`，行的计算在 `utils/drafts.ts`。

## 退出小家

代码在 `cloudfunctions/api/leave.js`，页面 `pages/leave`、`pages/clear`。

- 只能自己退出，不做「移除对方」，不需要对方同意，没有缓冲期。两人同时退出时，后到的提示「对方已经退出」（条件更新 memberCount 为 2 才退得成）。
- 两人时：退出的人去一个新小家，成为创建者 a。默认带走完整副本（记账、清单、吃啥、想去、纪念日、攒钱、回顾记录、喵喵小结，以及分摊开关和预算），可以勾「不带副本，从空开始」，只影响自己。
  - 副本里的付款人、负责人、存入人跟着换：退出的人原来是 b 时 a↔b 互换。对方记的、改的，`by`、`editedBy` 清空，不带对方的 openid。
  - 只复制退出那一刻之前记的（ts ≤ 退出时间）。每次 `household.copy` 复制一批 100 条，新 id 由新小家和原 id 算出，中途失败重试不会重复。
  - 新小家没有会员；会员天数全部留给留下的人，会员订单仍挂在原小家，退款只扣原小家的天数。
- 留下的人：小家原样不动，邀请码重新生效；新加入的人补上空出的角色（创建者走了就补 a）。
- 只剩一个人时：设置里多「清空记录」，两档：只清对方记的（按记录人 `by` 不是自己；我建的目标里对方存的几笔一起去掉，已存金额跟着减），或全部清空（设置和会员不变）。清之前写明条数、提示先复制全部数据。
- 只剩一个人时退出：清空这个小家的全部记录，回到创建 / 加入；会员剩余天数作废（确认时写明）。
- 先走的人的副本还没复制完时，旧小家的记录是副本来源：留下的人清空、或只剩自己时退出，云端先替对方复制完（返回 waiting），再删。任何操作都删不到对方带走的副本。
- 退出到一半（旧小家已退、新小家没建成）：下次 `household.get` 按 `departed` 补建。
- 已经在小家里的人点开别人的邀请卡片：不加入、也不动原来的小家（云端 `household.join` 同样拒绝）。加入页说明要先退出（单人退出会清空；两人要退两次），给「留在现在的小家」「看看怎么退出」。邀请码记在本机 7 天，退出回到加入页时自动填好；加入成功或点「留在现在的小家」就忘掉。点自己发的卡片直接回主页。

## 注销账号

代码在 `cloudfunctions/api/leave.js` 的 `account.delete`，页面 `pages/account`。注销 = 删除自己的全部数据并退出，不能恢复；需要 `confirm: true`，小程序里先输入「注销」再点，点了还有确认框，并提示先「复制全部数据」。

- 不能删对方的账本，也不删对方带走的副本：
  - 两人时：从小家拿掉自己（不留退出记录），邀请码重新生效；共同的记录原样留给对方，其中记录人 `by`、修改人 `editedBy` 是我的抹成空（记录本身不是我一个人的，对方要继续用）。会员天数全部留给对方，沿用退出的规则。
  - 只剩自己时：先替先走的人把副本复制完（waiting），再清空这个小家的全部记录，成员清空，会员作废，规则同「只剩自己时退出」。
  - 没有小家也可以注销（只做下面两条）。
- 我退出过的小家里 `departed` 记着我的 openid、称呼、微信名字：抹成空，其余字段（新小家 id、是否复制）不动，对方的副本照常。
- 我现在所在的小家如果是退出时建的新小家，就是上面「只剩自己」或「两人」的情况，带走的副本随之删除（或留在对方手里的那份不动）。
- 会员订单（`orders`）按交易记录保留：订单号、商品、金额、天数、状态、时间、退款额，以及微信查单和退款对账必需的 `openid`；没有称呼、账本内容、截图。订单继续挂在原小家，注销后退款仍只扣原小家的会员天数。
- 截图识别的图片识别完就删，云存储里不留；`ai_usage`、`insights` 等只有汇总数字，没有 openid。
- 失败可以重来：先退出、再抹记录人、最后抹退出记录，没有小家时重来只做最后一步。唯一例外：只剩自己时删记录删到一半断了，小家 `purge` 为 true，要在控制台按 `householdId` 手动删剩下的记录。
- 本机：清掉缓存和本地存储（主题等设置也一并清掉）。

## 记账规则

- 共同支出统计时，排除 `cat === "结算"` 和 `split === "self"` 的记录。
- 小家有「两人分摊与结算」开关（`households.splitting`，默认关闭）。关闭时只记账：记账页统计本月所有支出（`summary.spending`，不含结算和收入），不显示怎么分和结算，新记的账为 `split: "self"`；打开后按下面的规则分摊和结算。
- 每条记录有 `flow`：`out` 支出、`in` 收入，没有 `flow` 的旧记录算支出。收入只能是 `split === "self"`，不参与共同支出和结算。
- 每条记录的 credit（对方欠付款人的金额）：
  - `split === "other"` 时为 amount；
  - `split === "ratio"` 时为 round(amount × (100 − ratio) / 100)，其中 ratio 是付款人自己承担的百分比（整数 0–100，例如 6:4 记为 60），四舍五入到分（金额单位为分，恰好半分时进位）；
  - 其余（half）为 amount / 2。
- net 的累加：payer 为 a 时加 credit，为 b 时减 credit。
- net 大于 0 表示 b 应付给 a；小于 0 表示 a 应付给 b；绝对值小于 1 视为已结清。
- 记为已结算：新增一条记录，amount 为 round(|net|)，payer 为欠款方，split 为 other，cat 为 结算，note 为 结算。
- 按月统计，月份由 date 的前 7 位（YYYY-MM）决定。
- 花销分析（`insight.get`）：口径同 `summary.spending`，所有支出、不含结算和收入、不管怎么分。本月和上月按分类对比；大额单笔是本月支出前 3 笔，再加上 ¥500 及以上的，最多 5 笔；走势是截至本月的近 6 个月每月支出。
- AI 月度小结（`insight.write`）：只把上面这份汇总写成文字发给千问，大额单笔带备注或商户名（截到 12 字），不发截图、明细和名字；每小家每天的次数见 `shared/contract.json` 的 `ai.summary`（`households.summaryQuota`），失败也算一次。
- 攒钱目标：进度只靠手动「存了一笔」（`goal.deposit`，`saved` 累加并记 `log`），存入不是支出，不进记账统计。每月要存 = 月初还差的 ÷ 本月到截止月（含）的月数，向上取整；已过截止月时是还差的全部；攒够了为 0。本月还差 = 每月要存 − 本月存入（不超过还差的）。省钱建议：前 3 个整月里除房租、水电网外各类的月均支出，取最多的 3 类，算少花 10% / 20% 每月能多存多少。
- 分类预算：按所有支出算（同 `summary.spending`），开了两人分摊也一样。记一笔 / 改一笔的返回里带这一类本月的 `budget: {cat, limit, used, before}`（没设预算或不是支出时不带）；小程序在刚跨过 80% 或超出 100% 时弹一次提示，只在小程序里，不发微信消息。

## 通用验收标准

- 在真机上用两个微信号测试，不只用开发者工具模拟器。
- 任一写入失败时，界面给出明确提示，不能静默丢数据。
- 删除操作需要二次确认。
- 触控区域不小于 44 像素。
- 首屏可操作时间在 4G 网络下不超过 3 秒。
