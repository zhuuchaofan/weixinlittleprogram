# 小家：两人共用微信小程序 开发方案 v2（交给 Codex）

版本日期：2026-10-20　状态：待老板确认后执行

## 1. 目标

把已有的「答谢宴」微信小程序改造成超凡和佳益两个人共用的生活应用，包含：共同记账、共同清单、今天吃啥、周末去哪、纪念日与回忆。

成功标准（建议）：上线体验版后连续 4 周，两人每周各打开至少 3 次，月底结算不再翻聊天记录。

- 不做支付。

## 4. 架构

```
微信小程序（原生 WXML / WXSS / JS）
   │  wx.cloud.callFunction
   ▼
云函数 api（所有数据读写的唯一入口，校验 household 成员身份）
云函数 ai-suggest（AI 接口占位）
   │
   ▼
CloudBase 数据库（集合权限设为仅云函数可读写）
```

要点：

- 小程序端不直接读写数据库，一律通过云函数 `api`。这样权限只在一处校验，两人的数据不会被其他人读到。
- 身份用微信 openid。两人通过邀请码绑定到同一个 household。
- 每条业务记录都带 `householdId`、`ts`（创建时间戳）、`by`（记录人 openid）。

### household 绑定流程

1. 第一个人打开小程序，选择「创建小家」，云函数生成 6 位邀请码，写入 `households`。
2. 第二个人选择「加入小家」，输入邀请码，云函数把 openid 加入 `members`。
3. `members` 最多 2 人，满了之后邀请码失效。
4. 每个成员在 `members` 里有一个角色标记 `a` 或 `b`（创建者为 `a`）和显示名。

## 5. 数据模型

| 集合       | 字段                                                      | 说明                                                                                                               |
| ---------- | --------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------ |
| households | members[{openid, role, name}], inviteCode, city, currency | 默认 city 为东京，currency 为 JPY，可修改                                                                          |
| expenses   | amount, note, cat, date, payer, split, ratio              | payer 为 a 或 b；split 为 half、self、other、ratio；ratio 为 0–100 的整数，只在 split 为 ratio 时有值，其余为 null |
| todos      | text, kind, who, done                                     | kind 为 shop、todo、chore；who 为 a、b、both                                                                       |
| dishes     | name, tag                                                 | tag 为 在家做、外食、外卖                                                                                          |
| wishes     | title, why, plan                                          | 周末想去的地方                                                                                                     |
| dates      | title, date, yearly                                       | 纪念日                                                                                                             |
| memories   | date, title, note                                         | 回忆时间线                                                                                                         |

以上集合都带 `householdId`、`ts`、`by`。

P1 阶段计划新增：expenses.recurId；todos.due、todos.repeat；meals（date、name）；memories.photo；wishes.link、wishes.note。

### 记账规则（必须按这个实现）

- 共同支出统计时，排除 `cat === "结算"` 和 `split === "self"` 的记录。
- 每条记录有 `flow`：`out` 支出、`in` 收入，没有 `flow` 的旧记录算支出。收入只能是 `split === "self"`，不参与共同支出和结算。
- 每条记录的 credit（对方欠付款人的金额）：
  - `split === "other"` 时为 amount；
  - `split === "ratio"` 时为 round(amount × (100 − ratio) / 100)，其中 ratio 是付款人自己承担的百分比（整数 0–100，例如 6:4 记为 60），四舍五入到分（金额单位为分，恰好半分时进位）；
  - 其余（half）为 amount / 2。
- net 的累加：payer 为 a 时加 credit，为 b 时减 credit。
- net 大于 0 表示 b 应付给 a；小于 0 表示 a 应付给 b；绝对值小于 1 视为已结清。
- 记为已结算：新增一条记录，amount 为 round(|net|)，payer 为欠款方，split 为 other，cat 为 结算，note 为 结算。
- 按月统计，月份由 date 的前 7 位（YYYY-MM）决定。

## 7. AI 接口约定

云函数 `ai-suggest`，对外契约固定，内部实现暂时为空。

输入：

```json
{
  "scene": "food",
  "context": {
    "text": "今天很冷，想吃清淡的",
    "city": "东京",
    "dishes": ["拉面", "咖喱饭"]
  }
}
```

`scene` 为 `food` 或 `weekend`。weekend 的 context 包含 `dur`、`mood`、`budget`、`trans`、`city`。

输出（food）：`{ "disabled": false, "items": [{ "name": "", "tag": "在家做|外食|外卖", "why": "" }] }`

输出（weekend）：`{ "disabled": false, "items": [{ "title": "", "why": "", "plan": "", "cost": "" }] }`

规则：

- 没有接模型时，返回 `{ "disabled": true, "items": [] }`。
- 小程序遇到 `disabled: true` 时，隐藏「让 AI 推荐」按钮，其余功能照常使用。
- 云函数里不要写死任何 API 密钥。以后接哪个模型，由我决定，只改这个云函数。
