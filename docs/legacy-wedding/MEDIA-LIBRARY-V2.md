# 统一照片库（V2）

状态：本地代码已实现并通过项目检查；云函数和小程序尚未部署，真实云数据与手机端尚未验收。

## 展示规则

- 每个原文件只保留一条媒体记录。图片的 `category` 是所属相册：`wedding`、`daily`、`baoji_0927`、`lintong_0928`；历史 `pending` 只在「全部照片」显示。所有已发布的公开图片都能在「全部照片」找到。
- `placements` 是可多选的精选位置：`cover`、`story`、`qiuqiu`、`buding`。照片仍留在所属相册；球球／布丁照片归「日常照」，封面至多一张。视频单独进入「视频」，不设照片相册或精选位置。
- 「照片与视频」总览首屏显示四个相册与视频入口，并提供「全部照片」。首页、我们的这一页、猫咪区按精选位置选图；故事和猫咪精选可进入所属相册。相册沿用网格、大图和现有视频播放器。
- 主人端分别编辑「所属相册」和「展示位置」。新增照片发布前必须选一个相册；草稿可暂存待分类内容。调整多个精选位置不会复制媒体记录或云文件。

## 数据与接口

仍使用 `photo_content/draft`、`photo_content/published` 和现有管理员 OpenID 鉴权。V2 文档写入 `schemaVersion: 2`，`photos` 内为一文件一记录；私密条目只留草稿，已发布文档与访客读取均不返回。云存储文件权限未改变，私密只控制页面及 API 展示，已知文件链接仍可能被访问。

新版 action：`getMediaLibrary`、`getMediaLibraryDraft`、`saveMediaLibraryDraft`、`publishMediaLibrary`。旧 `getPhotos`/`getPhotoDraft` 保持 `slot` 格式供旧客户端读取；首次 V2 草稿保存或发布后，旧 `savePhotoDraft`/`publishPhotos` 返回 `UPGRADE_REQUIRED`，避免覆盖多选位置。上传、检查引用、删除文件仍走原有鉴权接口。

新版小程序若先于云函数安装，读取接口收到旧云函数的 `NOT_FOUND` 时会临时改读 `getPhotos`/`getPhotoDraft`，让已发布照片继续展示、主人继续查看旧草稿。保存和发布仍要求新版云函数，界面会提示先部署；网络故障或其他服务端错误不会触发旧接口回退。

读取 V1 时按媒体类型和原文件 ID 合并旧 `slot` 记录：优先保留相册记录的 ID、说明、相册，合并精选位置；任一同文件记录私密则整张私密。只有精选位置的旧照片继续在「全部照片」；猫咪照片归「日常照」。读取转换不写回数据库，不删除云文件。V2 首次保存后，草稿成为规范结构；首次发布后，发布文档成为规范结构。

## 上线顺序与回退

1. 在云开发控制台分别导出或备份 `photo_content` 的 `draft`、`published` 原始文档，记录备份时间和当前云函数版本。不要只备份已发布内容。
2. 部署新版 `cloudfunctions/weddingApi`，保留 `ADMIN_OPENIDS` 和现有数据库、存储规则。先用旧版小程序验证访客读取与管理员旧写入仍正常（此时尚无 V2 文档）。
3. 上传新版小程序体验版。用主人账号读草稿、调整分类和精选位置，先保存草稿，再更新展示；发布前确认历史待分类和私密内容。第一次保存 V2 草稿后，旧管理版会收到升级提示；第一次发布 V2 后，旧访客版仍可读取兼容格式。
4. 用主人和访客两台手机检查五个入口、「全部照片」、首页封面、故事和猫咪精选跳转、大图、视频、私密过滤、历史照片、草稿与发布边界。最后按正常小程序审核与发布流程上线。

若需要回退代码，在恢复旧版管理写入前先从备份恢复两个原始文档；不要用旧管理版覆盖 V2 文档。云文件不随文档回退自动删除。真实云环境、微信隐私配置、合法域名和手机验收必须在线上单独确认。

## 本地验证

`npm run check` 覆盖类型、lint 与服务端/客户端单元测试；`npm run check:native` 检查 WXML/WXSS；`npm run test:ui` 检查多尺寸页面与交互。辅助浏览器预览不能代替微信真机与 CloudBase 验收。
