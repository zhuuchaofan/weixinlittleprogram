# 历史版本的部署与验收（存档）

1.0.0 到 1.8.2 各版本上传后的步骤和真机验收。这些版本都已经做完，只留着查"当时验过什么"。现在要做什么看 [DEPLOYMENT.md](../DEPLOYMENT.md)。

## 1.0.0 体验版（自用，不提交审核）

1.0.0 汇总了 0.9.x 之后的全部改动，变化见 [CHANGELOG.md](../CHANGELOG.md)。只给你们俩自己用，上传后在公众平台设为体验版即可，不提交审核。

### 部署

1. 重新部署 `cloudfunctions/api`（「上传并部署：云端安装依赖」）。查重、每日上限、没勾选的原因提示都要新版 `api`；之前部署过最新 master 也再部署一次，确保一致。
2. 确认 `api` 的函数配置仍是：超时 60 秒、环境变量 `DASHSCOPE_API_KEY` 在。
3. 开发者工具编译，上传体验版，版本号填 `1.0.0`，备注写「自用：主页、新界面、截图记账查重」。
4. 公众平台「版本管理」里把 1.0.0 设为体验版；两个人的微信号都在体验成员里。

### 真机验收（两个微信号）

主页和返回：

1. 打开是主页，底部没有 tab；右上角齿轮进设置，设置页返回主页。
2. 从主页进入记账、清单、吃啥、周末、纪念，每个页面左上角都能返回主页；各页下拉刷新正常。
3. 主页「记一笔」保存后回到主页，本月支出立刻更新，和记账页顶部一致。
4. 清单入口的「N 件没做完」和清单页一致；下一个纪念日和纪念页一致。

截图记账：

5. 从主页「截图记账」选 2 张有重叠的账单截图：重叠的只出现一次，日期、金额、商户正确。
6. 和已记过的账金额相同、日期差一天以内的，显示「可能已记过」且默认不勾；你们俩之间的转账默认不勾；每一笔没勾的都写了原因。
7. 同一张截图再导入一次：全部显示「已导入过」，勾上保存也不会多出账目。
8. 云开发控制台 `households` 里你们的小家 `billQuota.count` 等于今天识别的张数。

界面：

9. 各页面是新风格（暖橙粉、白卡片），iPhone 上底部按钮不挡住横条；等待识别时显示小猫动画。

## 1.1.0 清单 / 吃啥 / 想去 / 纪念日改版

### 部署

1. 重新部署 `cloudfunctions/api`（「上传并部署：云端安装依赖」）：「就吃这个」和「去过了」要新版 `api` 才能保存。不部署时页面能用，但这两个操作刷新后会消失。
2. 开发者工具编译，上传体验版，版本号填 `1.1.0`，备注写「自用：清单吃啥想去纪念日改版」。

### 真机验收（两个微信号）

清单：

1. 只有「购物」「待办」两个页签；以前的家务条目出现在待办里。
2. 顶部输入框输入后回车就加上，键盘不收起可以连续加；新条目是「一起」，不显示名字；点开条目改成某个人后，行尾显示名字。
3. 待办：勾掉的折叠在「已完成 N ▸」里，点开能看到；旁边「清除」确认后清空（含以前的家务）。
4. 购物：勾掉的出现在「买过的」小标签里，点一下回到清单上方；同名的只出现一个。

吃啥：

5. 顶部一排：全部 / 在家做 / 出去吃 / 外卖；以前的「外食」「店家」都在「出去吃」或对应类型下。
6. 在「外卖」下添加一个，它出现在外卖分组；在「全部」下添加的存到在家做。
7. 抽到后点「就吃这个」：按钮变「记下了」，列表里这一条显示「今天吃过」；对方刷新也能看到。再抽几次，3 天内吃过的不会被抽到（这一类全吃过时才会抽到）。
8. 点开一条可以改名字和「怎么吃」，以前的店家改成「在家做」也能保存。

想去：

9. 主页入口和页面标题都是「想去」；顶部输入回车就加上。
10. 以前写过「为什么想去」「怎么安排」的，编辑页里合在「备注」一栏，保存后不丢。
11. 点前面的圈：显示「去过啦」，这一条移到「去过的 N ▸」里，写着今天的日期；编辑页能改成别的日期；再点一下圈取消。

纪念日：

12. 主页入口和页面标题都是「纪念日」；最近一个还没到的在顶部大卡片，显示第几年、还有几天、日期，点开能编辑。
13. 其余的在下面列表；不再有「回忆时间线，之后开放」；答谢宴入口在最下面。

记账：

14. 一个月超过 30 笔时，明细先显示 30 笔，底部写「继续往上滑，显示更多」；滑到底自动多出 30 笔，全部显示后写「这个月的 N 笔都在这里了」。标题旁的笔数始终是整月的。
15. 滑到后面点开一笔改完返回，列表还在原来的位置附近，没有缩回 30 笔。

主题：

16. 第一次打开是香芋紫：导航栏、按钮、卡片、开关、勾选圈、主页四个入口图标都是紫色系，没有残留的橙色（分类颜色、出错的红色除外）。
17. 设置 →「主题」点抹茶绿：设置页立刻变绿；返回主页、进记账、清单、截图记账（等待小猫）都是绿色。
18. 彻底关掉小程序再打开，仍是刚选的主题；另一个人的手机不受影响。

## 1.1.1 整理（功能不变）

### 部署

1. 不用部署云函数。
2. 开发者工具里先「清缓存 → 全部清除」再编译（页面目录改了名），跑一次 `npm run check:native`；上传体验版，版本号填 `1.1.1`，备注写「自用：代码整理」。

### 真机验收

1. 主页和欢迎页的标题是「喵喵记一笔」。
2. 每年重复的纪念日：主页大卡片写「名字 N 周年 还有」+ 天数（第 0 年即当年新加的不写周年）；纪念日页和列表写「N 周年」，不再是「第 N 年」。
3. 主页四个入口都能进去，图标颜色跟主题一致；点两人卡片进纪念日。
4. 主页、记账、清单、吃啥、想去、纪念日的样子和 1.1.0 一样：渐变大卡片右上角有淡白圆，清单和想去的勾选圈正常，输入框和列表间距没变。
5. 每页下拉刷新正常；断网时下拉刷新显示出错提示，联网后再刷新恢复。
6. 清单：加一条、勾选、取消、清除已完成，点开编辑保存和删除都正常；主页「N 件没做完」跟着变。

## 1.2.0 花销分析

### 部署

1. 重新部署 `cloudfunctions/api`（「上传并部署：云端安装依赖」）：花销分析要新版 `api`，没部署时进去会提示「不支持的操作」。
2. 不用新建集合，也不调用千问。
3. 开发者工具编译，上传体验版，版本号填 `1.2.0`，备注写「自用：花销分析」。

### 真机验收

1. 记账页分类统计最下面有「和上月比、大额支出 ›」，点进去标题是「花销分析」，月份和记账页一致。
2. 顶部大卡片：本月支出合计和记账页（不开分摊时）一样；下面写「比上个月多/少 ¥…（…%）」，自己拿上个月的合计算一下对得上。有收入时另写一行「本月收入」。
3. 「按分类，和上个月比」：每类金额和记账页一致；多了写 ▲ 加金额，少了写 ▼，上个月没有的写「新增」，上个月有、这个月没有的排在最后。
4. 「大额单笔」：本月最大的 3 笔，再加上 ¥500 以上的，最多 5 笔；点一笔能打开编辑。
5. 「近 6 个月」：本月那根是深色；切到上个月，各项跟着变；本月时右箭头是灰的。

## 1.3.0 AI 月度小结

### 部署

1. 云开发控制台 → 数据库 → 新建集合 `insights`，权限选「自定义安全规则」：`{ "read": false, "write": false }`。
2. 重新部署 `cloudfunctions/api`（「上传并部署：云端安装依赖」）。沿用截图记账的 `DASHSCOPE_API_KEY` 和模型，不用另配；超时仍是 60 秒。
3. 开发者工具编译，上传体验版，版本号填 `1.3.0`，备注写「自用：AI 月度小结」。

### 真机验收

1. 花销分析页大卡片下面有「喵喵小结」卡片，没生成过时写着说明和「写小结」按钮；这个月没有支出时不显示。
2. 点「写小结」：显示「喵喵正在看账本…」，十几秒后出现 3～5 句话，提到的金额和下面的数字对得上，大额单笔用的是备注或商户名。
3. 退出再进、或者另一个人打开：直接显示存好的小结和生成时间，不会再转圈。
4. 再记一笔后回来：小结下面写「生成之后这个月的账有变动，可以重新生成」；点「重新生成」后更新。
5. 同一天点到第 6 次：提示「今天已经生成了 5 次小结，明天再来吧」。控制台 `households` 里 `summaryQuota.count` 是 5，`insights` 里这个月只有一条。
6. 切到上个月也能单独生成；用量在千问 AI 平台里查，每次不到 1 分钱。

### 部署

1. 云开发控制台 → 数据库 → 新建集合 `goals`，权限选「自定义安全规则」：`{ "read": false, "write": false }`；索引加 `householdId` 升序。

3. 开发者工具编译，上传体验版，版本号填 `1.4.0`，备注写「自用：攒钱目标」。

### 真机验收（两个微信号）

1. 主页本月支出下面有「攒钱」卡片；没有目标时写「定一个目标」，点进去是「攒钱」页。
2. 点「新目标」：填名字、目标金额、最晚哪个月攒够（默认一年后）、已经攒下的，保存后回到列表。卡片上「还剩 N 个月，每月要存 ¥…」自己算一下对得上（本月也算一个月）。
3. 点「存了一笔」输入 500：进度条和百分比变了，「本月还差」少了 500，「每月要存」不变。另一个人刷新也看到；点「编辑」能在「最近存入」里看到日期和谁存的。
4. 记账页的支出不受「存了一笔」影响。
5. 编辑里改名字保存，已存金额不变；把已存改成目标金额，卡片显示「攒够啦」、进度条变绿，排到列表最后。
6. 「从哪儿省」：列出前 3 个月里花得最多的 3 类（不含房租、水电网），月均和少 10% / 20% 能省多少。没有前几个月的账时不显示。
7. 删除目标要确认；删除后主页卡片换成下一个目标或「定一个目标」。

## 1.5.0 分类预算

### 部署

1. 重新部署 `cloudfunctions/api`（「上传并部署：云端安装依赖」）。不用新建集合，不调用千问。
2. 开发者工具编译，上传体验版，版本号填 `1.5.0`，备注写「自用：分类预算」。

### 真机验收（两个微信号）

1. 设置 →「记账」下有「分类预算」，点进去每类一行，上个月花过的写着「上月 ¥…」。给吃饭填 100、娱乐填 50，保存。
2. 另一个人打开同一页能看到同样的数；把娱乐清空保存，第一个人再打开，娱乐是空的（不是留着旧的 50）。
3. 记账页分类统计里，吃饭下面多一行进度条和「预算 ¥100 · 用了 N%」；不到 80% 是绿色，80% 起是主色，超出变红并写「超出 ¥…」。没设预算的分类不显示。
4. 记一笔吃饭让本月吃饭刚到 80%：保存后弹「吃饭预算用了 8x%」，点「知道了」返回。再记一笔让它超过 100%：弹「吃饭超预算了」。之后再记吃饭不再弹（已经超过了）。
5. 记收入、记没设预算的分类都不弹；改一笔让吃饭从 70% 变成 90% 也会弹。

## 1.5.1 喵喵小结修复

### 部署

1. 重新部署 `cloudfunctions/api`（「上传并部署：云端安装依赖」）。不用新建集合；超时仍是 60 秒。
2. 可选：小结写得还是慢，在 `api` 的环境变量里加 `SUMMARY_MODEL`，填一个更快的纯文本模型（例如 `qwen-flash`，要在千问 AI 平台开通）。不填就和截图识别用同一个模型。
3. 开发者工具编译，上传体验版，版本号填 `1.5.1`，备注写「自用：喵喵小结修复」。

### 真机验收

1. 点「重新生成」：比原来快，写完不再出现「网络或云端暂时不可用」。
2. 生成时切到别的 App 再回来：等一会儿显示新小结，没有报错。
3. 开始记账的第一个月：小结不比较（不说「上月为 0」「增加最明显」）；大卡片写「这是记账的第一个月」，分类标题是「按分类」，右边不写「新增」。
4. 上个月空着、更早有账：小结提一句上个月没记账，拿最近有账的月份比；大卡片写「上个月没记账，比 N月多/少 …」，分类标题「按分类，和 N月比」。
5. 上个月是中途开始记的（比如 21 号起）：照比，大卡片写「（上个月只记了 10 天）」不算百分比，小结也说明只记了几天；分类右边不写「新增」。
6. 上个月记满的月份：照旧比上个月，有百分比，分类右边写 ▲/▼/新增。

## 1.7.0 AI 地基

界面基本不变：AI 调用走统一入口（记用量、全站费用上限、写文字类总开关），会员页的权益列表按 `shared/contract.json` 的 `ai` 生成，截图记账的确认列表做成了组件，线上出错会记日志，开始给年度回顾攒数据。

### 部署

1. 云开发控制台 → 数据库 → 新建集合 `activity`（索引加 `householdId` 升序）和 `ai_usage`（不用索引），权限都选「自定义安全规则」`{ "read": false, "write": false }`。没建也不会报错，只是不记。
2. 可选：`api` 环境变量加 `AI_DAILY_BUDGET`（默认 20 元）。
3. 重新部署 `cloudfunctions/api`；开发者工具「清缓存 → 全部清除」后编译，上传体验版，版本号填 `1.7.0`。

### 真机验收

1. 截图记账识别一张：确认列表和以前一样（勾选、点开改金额 / 备注 / 日期 / 分类 / 收支、保存）。
2. 云开发控制台 → 数据库 → `ai_usage`：今天的日期有一条，`calls` 是 1，`features.billImage` 下有 token 数和 `cost`；云函数 `api` 的日志里有一行 `"event":"ai"`，里面没有账单内容。
3. 写一次喵喵小结：`ai_usage` 里多出 `features.summary`。
4. 在 `api` 环境变量加 `AI_WRITE_OFF=1` 再部署：写小结提示「喵喵写文字的功能暂时关闭了」，截图识别照常。验完删掉再部署。
5. 会员页「会员权益」两行：截图记账每天识别 100 张（不开通时 5 张）、喵喵小结每天生成 30 次（不开通时 5 次）。
6. 吃啥点「就吃这个」、清单勾完一条待办、想去打勾「去过了」：`activity` 里各多一条；待办取消勾选，那条消失。「清除已完成」后 `activity` 里的还在。
7. 小程序后台 → 开发管理 → 运维中心 → 实时日志：断网时点一次刷新，能搜到 `api` 和 `NETWORK`。

## 1.8.0 微信账单文件导入

记账页、主页的「截图记账」改叫「导入账单」，点开选「账单截图」或「微信账单文件」。微信账单文件在手机上读，文件不上传；只把每笔的时间、类型、交易对方、收/支、金额、状态、交易单号发给 `api`，交易单号只算成指纹，不保存。不用 AI，不占识别次数。

### 部署

1. 公众平台「设置 → 服务内容声明 → 用户隐私保护指引」：信息类型里勾上「选中的文件」，用途写「读取你选择的微信账单文件生成记账记录，文件只在手机上读取，不上传」。不勾的话选文件会失败。
2. 重新部署 `cloudfunctions/api`；开发者工具「清缓存 → 全部清除」后编译，上传体验版，版本号填 `1.8.0`。

### 真机验收

1. 微信：我 → 服务 → 钱包 → 账单 → 右上角「…」→ 下载账单 → 用于个人对账，等微信支付发来「账单流水文件」通知，点「查看详情」打开文件，用右上角「…」发送给「文件传输助手」。
2. 记账页点「导入账单」→「微信账单文件」：第一次先弹「怎么拿到账单文件」，点「去选文件」，从聊天里选那个 Excel。
3. 几秒后进确认列表：顶部写读出多少笔、跳过了多少（提现等不计收支、退款已从原账扣掉）；月份一排可以切换，「本月全选 / 全不选」。
4. 抽查：部分退款的那笔金额是净额，备注带「已退¥…」；全额退款的不在列表里；亲属卡的备注是「亲属卡·昵称」；转给对方的转账显示「你们俩之间的转账，默认不记」（要对方在小家里的名字和微信里的一样才认得出）。
5. 之前用截图导入过的那几笔显示「已导入过」。
6. 点保存：超过 100 笔时按钮上显示保存进度。保存后再导一次同一个文件，全部是「已导入过」。
7. 设置里填「我的微信名字」保存；让对方也填。再导入含你们之间转账的账单，这些转账显示「你们俩之间的转账，默认不记」。
8. 导入一批后，把某个商户改成别的分类保存；下次导入同一商户，分类自动是你改过的那个。

## 1.8.1 支付宝账单文件导入

「导入账单」里多了「支付宝账单文件（CSV）」。文件在手机上读、不上传；支付宝的 CSV 是 GBK 编码，手机上按字节切开，文字列原样发给 `api` 解码，只发时间、分类、对方、商品说明、收/支、金额、状态、订单号这几列，银行卡、对方账号、商家订单号不出手机。不用 AI，不占识别次数。隐私指引里「选中的文件」1.8.0 已经声明过，不用再改。

### 部署

重新部署 `cloudfunctions/api`；开发者工具「清缓存 → 全部清除」后编译，上传体验版，版本号填 `1.8.1`。没有新集合。

### 真机验收

1. 支付宝：账单 → 右上角「…」→ 开具交易流水证明 → 用于个人对账 → 申请，选好时间和接收方式，拿到 CSV 后发送到微信「文件传输助手」。
2. 记账页点「导入账单」→「支付宝账单文件」：第一次先弹说明，点「去选文件」，从文件传输助手里选这个 CSV。
3. 几秒后进确认列表，按月切换；顶部写读出多少笔、跳过多少（余额宝、提现等不计收支；退款已从原账扣掉）。
4. 抽查：外卖是店名（不是「淘宝闪购」）；退过款的那笔是净额、备注带「已退¥…」；分类和支付宝里的分类大致对得上；对方（在小家里）转来的钱显示「你们俩之间的转账，默认不记」。
5. 保存后再导一次同一个文件，全部是「已导入过」。

## 1.8.2 退出小家

设置最下面多了「小家」一块：「退出小家」，只剩自己时还有「清空记录」。规则见 `docs/PLAN.md`「退出小家」。没有新集合，`households` 里多了 `departed`、`copy` 两个字段，云端自己写。

### 部署

1. 云开发控制台 → 数据库 → `households` → 索引管理：新建索引，字段 `departed.openid`，升序，非唯一（退出到一半补建新小家时按它查；不建也能用，只是慢一点）。
2. 重新部署 `cloudfunctions/api`；开发者工具「清缓存 → 全部清除」后编译，上传体验版，版本号填 `1.8.2`。

### 真机验收

最好用两个微信号（A、B）在一个测试小家里做，先各记几笔账、一条指派给对方的待办、一个攒钱目标各存一笔。

1. B：设置 → 退出小家。页面写明带走副本、会员留给 A；点「退出小家」，确认框里写着会带走副本。确认后显示「正在复制旧账 已复制 N 条」，完了自动回主页。
2. B 的新小家：B 是创建者，有新的邀请码，没有会员；记账页里原来 B 付的账付款人是自己，A 付的是「对方」；指派给 A 的待办现在是「对方」；攒钱目标的金额和几笔存入都在。
3. A：小家原样，成员只剩自己，会员不变，设置里有新的邀请码。
4. A：设置 → 清空记录。两档都写着条数；选「只清对方记的」→ 确认框写明删几条 → 删掉后 A 记的还在、B 记的没了。再看 B 那边，副本一条没少。
5. A：设置 → 退出小家（只剩自己）。写明会清空、会员会作废；确认后回到「创建 / 加入」。可以重新创建，或用 B 的邀请码加入 B 的新小家（加入后是 b）。
6. 断网重试：B 退出时在「正在复制」时关掉网络，看到出错和「重试」；打开网络点重试，复制完后条数没有重复。中途直接杀掉小程序，再打开时主页顶部提示「旧账还没复制完」，点「继续复制」。
7. 同时退出：A、B 同时点退出，后点的那个提示「对方已经退出了」，页面变成「只剩你一个人」。

只剩一人时退出后，原小家文档留着（会员订单挂在上面），`members` 为空；`purge` 为 true 的是删记录中途断了的，可以在控制台按 `householdId` 手动删掉它的记录。
