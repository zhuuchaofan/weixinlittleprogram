# 云端准备与验收

以下操作需要登录微信后台或开发者工具，由你本人执行。前半部分是「云端应该是什么样」（新环境照着从零配一遍也行），后半部分是每个版本上传后的真机验收。1.0.0 到 1.20.0 的步骤已做完，存档在 [archive/DEPLOYMENT-HISTORY.md](archive/DEPLOYMENT-HISTORY.md)。

## 每次发版的固定步骤

1. 改了 `cloudfunctions/` 的版本：重新部署 `api`（右键 `cloudfunctions/api` →「上传并部署：云端安装依赖」）。只改了小程序的版本不用。
2. 开发者工具「清缓存 → 全部清除」后编译，跑一次 `npm run check:native`，上传。**版本号只有一个来源：`package.json` 的 `version`**，上传时照着填；`CHANGELOG.md` 最新一节的标题要和它一致（有自动测试检查）。
3. 在公众平台设为体验版，两人真机按 [DEVICE-TEST.md](DEVICE-TEST.md) 和本版的验收走一遍。
4. 提交审核后，在 git 上给对应提交打 tag（如 `v1.8.2`），之后就能说清"线上是哪一版、master 比线上多了什么"。
5. 本文件只写"云端应该是什么样"和"还没测的版本"；某个版本测完、上线后，把它那一节挪进 `archive/DEPLOYMENT-HISTORY.md`。

## 1. 数据库

所有集合的权限都设为「自定义安全规则」：`{ "read": false, "write": false }`。小程序只通过云函数 `api` 读写，不需要放宽。

| ------------------------- | ------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------- |

| `expenses`                | `householdId` 升序 + `date` 升序                                                      | 记账                                                                                                                                |
| `todos`                   | `householdId` 升序                                                                    | 清单                                                                                                                                |
| `dishes`                  | `householdId` 升序                                                                    | 吃啥                                                                                                                                |
| `wishes`                  | `householdId` 升序                                                                    | 想去                                                                                                                                |
| `dates`                   | `householdId` 升序                                                                    | 纪念日                                                                                                                              |
| `goals`                   | `householdId` 升序                                                                    | 攒钱目标（1.4.0 起）                                                                                                                |

## 2. 云函数 `api`

1. 开发者工具中右键 `cloudfunctions/api` →「上传并部署：云端安装依赖」。每次合并改了 `cloudfunctions/` 都要重新部署。
2. 云开发控制台 → 云函数 → `api` → 函数配置：
   - **超时时间 60 秒**（识别一张截图要 5～15 秒，默认 3 秒会超时）；
   - 环境变量 `DASHSCOPE_API_KEY`：千问的 API Key（见下）。密钥只放这里，不要写进代码或提交到 git；
   - 可选：`BILL_MODEL` 换模型（默认 `qwen3.8-omni-flash`）；`SUMMARY_MODEL` 单独换喵喵小结的模型（例如 `qwen-flash`）；`ASSIST_MODEL` 单独换一句话类功能（一句话加清单）的模型（不填用 `SUMMARY_MODEL`，再没有用 `BILL_MODEL`）；`BILL_BASE_URL` 换接口地址（默认 `https://cn-beijing.maas.qianwenaiapi.com/compatible-mode/v1`）；
   - 可选：`AI_DAILY_BUDGET` 全站每天 AI 费用上限，单位元，默认 20。到 80% 先停「写文字」的功能（喵喵小结），到 100% 再停截图识别，第二天自动恢复；
   - 可选：`AI_WRITE_OFF` 填 `1` 时关掉所有「写文字」的 AI 功能（审核要求下架时用，不用发版），截图识别不受影响。
   - 可选：`WEEKLY_STATE` 点每周小结消息打开哪个版本，`trial`（体验版）/ `developer`（开发版）/ `formal`（正式版，默认）。体验版测试时填 `trial`，上线后删掉。
3. 定时触发器（1.23.0 起）：开发者工具右键 `cloudfunctions/api` →「上传触发器」。配置在 `cloudfunctions/api/config.json`：`weeklyReport`，每周一 9:00、9:20、9:40 各跑一次（后两次只补第一次没处理完的，同一周不会重复发）。「上传并部署」不会带上触发器，改了 `config.json` 要单独上传一次。
4. 云存储不用新建目录：截图临时上传到 `bill-screenshots/`，识别完马上删除。

### 开通通义千问（截图记账）

1. 登录千问 AI 平台（原阿里云百炼），开通模型服务；在「模型」里确认 `qwen3.8-omni-flash` 可用。
2. 在「API-KEY」页面创建一个 API Key（`sk-` 开头），填到上面的环境变量。建议在阿里云「费用」里设一个每月预算提醒，比如 20 元。
3. 用量参考：每天 3～4 张截图，每月约 100 张，每月不到 1 元。以千问 AI 平台显示的价格为准。没配 Key 时点「截图记账」会提示还没开通，不影响其他功能。

### 隐私保护指引

公众平台「设置 → 服务内容声明 → 用户隐私保护指引」里要有：收集「选中的照片或视频信息」，用途「识别账单截图生成记账记录」；截图会交给第三方（阿里云通义千问）识别、识别后删除。AI 月度小结会把当月按分类的支出汇总和大额单笔的备注交给千问生成文字，也要写进补充说明。设置里「复制邀请码」「复制全部数据」会写剪切板，信息列表里有「剪切板」就一并勾选。

## 会员订阅（微信虚拟支付，道具直购）

会员属于整个小家，一人开通两人共用；权益是年度回顾、账单文件导入和更多 AI 次数（套餐见 `shared/contract.json` 的 `vip`，各功能免费 / 会员次数见 `ai`，改完跑 `npm run contract`）。

1. 云开发控制台 → 数据库 → 新建 `orders`，权限选「自定义安全规则」`{ "read": false, "write": false }`；加索引 `outTradeNo`（唯一）。
2. 公众平台 → 虚拟支付：开通后在「基本配置」取 OfferID、现网 AppKey、沙箱 AppKey；在「道具管理」建两个道具，**道具 ID 和价格必须和 `contract.json` 里的套餐一致**（`vip_month` 9 元、`vip_year` 68 元，`contract.json` 里价格单位是分）；活动价另有 `vip_month_promo`、`vip_year_promo` 两个道具，见下面 1.24.0。
3. 云函数 `api` 环境变量：`XPAY_OFFER_ID`、`XPAY_APP_KEY`、`XPAY_SANDBOX_APP_KEY`、`WX_APPID`、`WX_APPSECRET`（AppID 和 AppSecret 在公众平台「开发管理 → 开发设置」）；联调时加 `XPAY_ENV=1` 走沙箱，上线前删掉。缺任何一项，会员页显示「还没开通」。
   - 可选：`VIP_FREE_UNTIL` 覆盖限时免费的截止日（默认 `shared/contract.json` 的 `vip.freeUntil`）：填 `2027-01-15` 这样的日期延长，填 `off` 立刻结束；改完重新部署 api，不用发版。
   - 可选：`VIP_PROMO_UNTIL` 覆盖活动价的截止日（默认 `vip.promo.until`），填 `off` 立刻恢复原价，见下面 1.24.0。
4. 云开发控制台 → 设置 → 其他设置 → 消息推送：加两条，消息类型都是 `event`、云函数都是 `api`，事件分别是 `xpay_goods_deliver_notify`（发货）和 `xpay_refund_notify`（退款）。
5. 重新部署云函数 `api`。发货时云函数会调微信的 `stable_token` 和 `xpay/query_order`；如果「开发设置」里开了 API IP 白名单，要关掉（云函数的出口 IP 不固定），否则查单失败、会员不到账。
6. 到账只以发货推送为准：推送本身不带签名，云函数会先向微信查单，订单状态是已支付、金额等于套餐价才加天数。同一订单重复推送不会重复加天数。
7. 小程序付款成功后还会调 `vip.confirm` 主动查单开通：沙箱不发发货推送，现网推送也可能丢，两条路都以微信查单为准、只加一次。
8. 付款时报 -15001（参数错误）：多半是虚拟支付还没绑定微信支付商户；-15005/-15006 是签名错，-15013 是价格和道具不一致，-15014 是道具刚发布还没生效。

### 会员验收（`XPAY_ENV=1` 沙箱）

1. A 在设置 → 会员买月度会员，付款后几秒内显示「开通成功」，到期日是今天往后 31 天；B 打开设置也显示「会员有效中」。
2. 再买一次月度：到期日在原来的基础上再加 31 天。
3. 云开发控制台 → 数据库 → `orders`：两条都是 `delivered`。
4. 在收银台点取消：提示「已取消支付」，`orders` 里那条停在 `pending`，会员不变。
5. 会员截图记账、喵喵小结能用到会员次数（数字见 `shared/contract.json` 的 `ai`，例如截图记账会员每天 100 张）。
6. 非会员用完次数：截图记账、喵喵小结的提示里多一句「开通会员每天可以……」，下面有「看看会员」，点了进会员页。
7. 会员页：一页只有一个「开通 / 续费」按钮，点套餐行切换选中；下面有「购买须知」；设置页那一行显示到期日。
8. 联调通过后删掉 `XPAY_ENV`，重新部署 `api`，用现网小额买一次确认。

### 退款

在虚拟支付后台「交易订单」点退款（或处理投诉退款）成功后，微信推 `xpay_refund_notify` 到 `api`，云函数自动扣回会员：

1. 推送不可信，同样先向微信查单，按「订单价 − 剩余金额」算一共退了多少。
2. 全额退款扣回这一单的天数；部分退款按比例扣。只扣这一单，别的订单加的天数不动；扣完早于现在就等于会员已结束。
3. 扣到多少记在 `households.vip.refunded`（按订单号），`orders` 那条记上 `refunded`（分），重复推送只扣一次。
4. 还没开通的订单被退款：只在 `orders` 记上 `refunded`，之后也不会再开通（微信查单状态已不是「已支付」）。

验收：沙箱买一次月度、到账后在后台退款，几秒后会员页到期日往回减 31 天，`orders` 那条有 `refunded: 900`。如果没变，看 `api` 的调用日志里有没有收到 `xpay_refund_notify`；没收到就是后台退款不发推送，这时按下面手动扣：

1. 数据库 `orders` 按 `outTradeNo` 找到那笔，记下 `householdId` 和 `days`。
2. `households` 找到这个小家，把 `vip.until` 减去 `days × 86400000`。减完小于现在的时间就等于会员已结束。

## 1.23.0 每周小结订阅消息

公众平台「订阅消息」里选的一次性模板「记账周报通知」（模板 ID `vsDp7r72wFcsDI3dn3ChPDN_u-6Yy3QJuMLd2jGvZOI`，写在 `cloudfunctions/api/weekly.js` 和 `miniprogram/services/weekly.ts`，换模板两处一起改）。字段：账本名称 `thing1`、起止时间 `time2`、上周支出 `amount3`、上周结余 `character_string8`、备注 `thing5`。

### 真机验收

真机上能看到的部分：

1. 打开「我们的小报」，拉到最下面有一张「每周一收到上周小结」卡片（云端没部署时不出现）。点「订阅」→ 微信弹窗「记账周报通知」→ 点「允许」：轻提示「已订阅」，左下角「已订阅，还能收 1 次」，按钮变「再订一周」，下面多一个「不用了」。
2. 再点「再订一周」→ 允许：变成「还能收 2 次」。点「不用了」：提示「不会再发了」，回到「订阅」。
3. 弹窗里点「取消」：卡片里写「这次没订上，想收的时候再点「订阅」就好。」，次数不变。
4. 控制台 → 数据库 → `subscriptions`：有一条 `_id` 是你的 openid，`weekly` 等于页面上的次数。

发消息要等周一，可以不等，手动触发一次：

1. 先在小报页订阅一次（`weekly` ≥ 1），并且**上周**（周一到周日，按今天往前算）小家里有记账；没有的话在记一笔里把日期改到上周记一笔。
2. 控制台 → 云函数 → `api` →「云端测试」，请求参数填 `{"Type":"Timer","TriggerName":"weeklyReport"}`，运行。返回 `{"ok":true,"data":{"week":"上周一","sent":1,"skipped":0,"failed":0,"more":false}}`。
3. 手机微信「服务通知」里来一条「记账周报通知」：账本名称「A和B的小账本」（名字太长时是「我们的小账本」）、起止时间「上周一~上周日」、上周支出「¥金额」、上周结余（收入减支出，没记收入时是负数）、备注（比前一周花得少时「比前一周少花了 N 元，真棒」，否则「记了 N 笔，X 花得最多」）。点开进主页（`WEEKLY_STATE=trial` 时打开体验版）。
4. `subscriptions` 里 `weekly` 少了 1，`week` 是上周一。再运行一次云端测试：`sent` 是 0，不会重复发。要再测，把 `week` 改成空字符串、`weekly` 改回 1。
5. 两个人都订了时两人各收一条。上周没记账的小家：`skipped` 加 1，次数不扣。
6. `failed` 不是 0 时看云函数日志里的 `{"event":"weekly","error":…}`：`43101` 是没授权或用完（次数会清零），`47003` 是字段格式不对（次数还回去，把那行日志发我），`40001` 一类是 access_token（检查 `WX_APPID`、`WX_APPSECRET`）。
7. 注销账号后 `subscriptions` 里自己那条没了。

## 1.24.0 会员限时活动价

扣款金额由虚拟支付后台的道具价格决定，下单时传的 `goodsPrice` 必须和后台价格一致，所以活动价要另建两个道具。原价道具 `vip_month`、`vip_year` 保留不动，活动结束后自动换回它们。

### 部署（按顺序，先发布道具再部署 api）

1. 虚拟支付 → 基本配置 → 道具配置 →「添加道具」，建两个（图片用原来的 `/mnt/project-files/vip/道具图片-200.png`）：

   | 道具 id           | 道具名称           | 价格（元） | 备注说明      |
   | ----------------- | ------------------ | ---------- | ------------- |
   | `vip_month_promo` | 月度会员（限时价） | 6          | 「31天会员」  |
   | `vip_year_promo`  | 年度会员（限时价） | 38         | 「366天会员」 |

   道具 id 必须和 `shared/contract.json` 里每个套餐 `promo.productId` 一字不差。

2. 两个新道具「发布」到现网，确认在「线上版本」里能看到。没发布就部署 api，活动期间买会员会失败。
3. 重新部署云函数 `api`（右键 →「上传并部署：云端安装依赖」）。部署后旧版小程序的会员页也会显示活动价并按活动价下单（旧版没有划线和角标）。
4. 上传 1.24.0 体验版。

### 改价格、改日期、提前结束

- 只改截止日期或提前结束：云函数 `api` 的环境变量 `VIP_PROMO_UNTIL` 填 `2027-01-15` 这样的日期（北京时间这天结束），填 `off` 立刻恢复原价；改完重新部署 api，不用发版。
- 改活动价：先在虚拟支付后台建一个新价格的道具（已发布道具的价格不要直接改，正在付款的人会对不上），再把 `shared/contract.json` 里对应套餐的 `promo.price`（单位分，6 元写 600）和 `promo.productId` 改成新的，运行 `npm run contract`，协议 docs/VIP-AGREEMENT.md 里的活动价一起改并运行 `npm run agreement`，重新部署 api。
- 默认截止日期在 `shared/contract.json` 的 `vip.promo.until`。
