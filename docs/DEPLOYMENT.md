# 云端准备与验收

以下操作需要登录微信后台或开发者工具，由你本人执行。

## 1. 数据库

1. 在云开发控制台新建集合 `households`，权限设为「自定义安全规则」：`{ "read": false, "write": false }`。
2. 确认旧集合 `rsvps`、`guest_messages` 仍在，规则保持 `{ "read": false, "write": false }`。归档页通过云函数读取，不需要放宽。
3. 旧集合 `photo_content`、`event_program` 不再使用，暂时不要删除。

## 2. 云函数

1. 开发者工具中右键 `cloudfunctions/api` →「上传并部署：云端安装依赖」。
2. `api` 不需要配置任何环境变量。
3. 后台已部署的旧函数 `weddingApi` 新版本不再调用，可以先保留；确认阶段 1 验收通过后再决定是否删除。

## 3. 验收

用两个微信号（真机）：

1. A 打开小程序 → 跳到「两个人的小家」→ 创建小家 → 在「纪念」页看到 6 位邀请码。
2. B 打开 → 用邀请码加入 → 进入「记账」tab。
3. A 回到「纪念」页刷新：邀请码消失，成员显示两人。
4. A 把城市改成任意值并保存；B 进入「纪念」页能看到新城市。
5. 第三个微信号用同一个邀请码加入，应提示「邀请码无效或已被使用」。
6. A、B 都能打开「答谢宴 · 登记与祝福」，人数和条数与原后台一致；第三个微信号无法读取。

## 阶段 2

1. 新建集合 `expenses`、`todos`，权限同样设为 `{ "read": false, "write": false }`。
2. 建议在 `expenses` 上添加索引：`householdId` 升序 + `date` 升序；`todos` 上添加 `householdId` 升序。
3. 重新部署 `cloudfunctions/api`（「上传并部署：云端安装依赖」）。

验收（两个微信号真机）：

1. A、B 各记 5 笔本月账，包含「两人平摊」「全算对方」「自己的」三种分摊；把每笔记下来手算：
   - 共同支出 = 除「自己的」外的金额合计；
   - 平摊记 1/2、全算对方记全额，A 付为正、B 付为负，合计为 net；net > 0 时 B 付给 A，四舍五入到 1 日元。
     页面上的共同支出、各自付款和结算金额应与手算一致。
2. 点「记为已结算」→ 出现一条结算记录，提示变为「本月已结清」；删除该结算记录后恢复原来的结算建议。
3. 编辑一笔账（改金额和付款人）、删除一笔账（有二次确认），对方刷新后能看到变化。
4. 清单：在三类里各加一条，指派给不同的人，勾选、取消勾选、编辑、删除；对方刷新后一致。
5. 「纪念」→「复制全部数据」，粘贴出来的文本能被任意 JSON 工具解析，条数与页面一致，里面没有 openid。
6. 断网时记一笔：页面提示失败，表单内容保留。

## 阶段 3

1. 新建集合 `dishes`、`wishes`、`dates`，权限设为 `{ "read": false, "write": false }`；各加索引 `householdId` 升序。
2. 重新部署 `cloudfunctions/api`；新部署 `cloudfunctions/ai-suggest`（没有依赖，「上传并部署：云端安装依赖」即可）。

验收（两个微信号真机）：

1. 吃啥：加 5 道菜（三种类型都有），按类型筛选后随机抽多次，结果都在当前类型里；编辑、删除一道菜（有二次确认），对方刷新后一致。
2. 周末：添加、编辑、删除收藏，对方能看到。
3. 纪念日：添加一个每年重复的（如结婚纪念日）、一个今天的、一个已过去且不重复的，核对「还有 N 天」「就是今天」「已经 N 天」和「第 N 年」。
4. 「吃啥」「周末」页面没有「让 AI 推荐」按钮，也没有报错；把 `ai-suggest` 暂时删掉或不部署时同样不报错。
5. 「复制全部数据」里包含 dishes、wishes、dates。
