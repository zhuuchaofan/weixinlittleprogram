# 真机测试清单：会员付款、平台异常扣款、账单导入

正式版提交前，用两个微信号在真机上走一遍。每一步写了「做什么」和「应该看到什么」，对不上就停下，记下截图和时间。

## 〇、准备

- **两个微信号**：A 用安卓手机，B 用 iPhone。两人在同一个测试小家里，开始前小家没有会员。
- **会真扣钱**：虚拟支付的沙箱也会真扣款（2026-10-27 实测），全程只买 9 元月度会员。测试用的订单在第三节由后台退回。
- **两种环境**：
  - 沙箱：云函数 `api` 有环境变量 `XPAY_ENV=1`，道具还在「开发版本」。安卓能买，iPhone 买不了（见第二节）。
  - 现网：两个道具已发布、删掉 `XPAY_ENV`、重新部署 `api`。iPhone 只能在现网测。
- **随手开着**：云开发控制台 → 数据库 `orders`、`households`；云函数 `api` 的日志；公众平台 → 虚拟支付 → 交易订单。
- 部署项已做完：`orders` 集合和 `outTradeNo` 唯一索引、`api` 的环境变量、消息推送里 `xpay_goods_deliver_notify` 和 `xpay_refund_notify` 两条都指向 `api`（见 `docs/DEPLOYMENT.md`「会员订阅」）。

## 一、付款（安卓，A）

1. A、B 分别打开 设置 → 会员。
   → 两边都显示「还不是会员 / 开通会员 / 一个人开通，两个人都能用」；两个套餐「月度会员 31 天 ¥9」「年度会员 366 天 ¥68」；只有一个「开通」按钮。
2. 看「购买须知」第 5 条。
   → 写的是「会员是虚拟商品，购买后不支持退款，未用完的天数也不能折现或转让。」，没有「一般」「可以申请」之类的字样。
3. A 选月度会员 → 开通 → 在收银台点取消。
   → 提示「已取消支付。」；`orders` 多一条 `pending`；会员不变；没有扣钱。
4. A 选月度会员 → 开通 → 付款。
   → 几秒内提示开通成功；会员页显示「会员有效中 · 你们两个人共用」，到期日是今天往后 31 天；`orders` 那条变成 `delivered`；交易订单里有这笔 9 元。
5. B 打开 设置 → 会员（下拉刷新一次）。
   → B 也是「会员有效中」，到期日和 A 一样。
6. A 再买一次月度会员。
   → 到期日在原来基础上再加 31 天（不是从今天算）；`orders` 两条都是 `delivered`。
7. 设置页「会员」那一行。
   → 两人都显示同一个到期日。

## 二、iPhone（B）和 -15011

1. **沙箱下**（还有 `XPAY_ENV=1`）：B 选月度会员 → 开通。
   → 收银台拉不起来或立刻失败，页面提示「支付没有完成（-15011：…），请重试。」；`orders` 多一条 `pending`；没有扣钱；会员不变。
   - 这是预期结果：-15011 是 `PAYMENT_ILLEGAL_IN_SANDBOX`，iOS 不支持虚拟支付沙箱，不是代码问题，不用修。
   - 如果提示的是 -15001，多半是道具或商户配置问题，对照 `docs/DEPLOYMENT.md` 第 8 条。
2. 切到**现网**：两个道具发布、删掉 `XPAY_ENV`、重新部署 `api`，等道具生效（刚发布时可能报 -15014，过几分钟再试）。
3. 现网下 B 买月度会员。
   → 弹出苹果的付款确认（不是微信支付密码）；付款后几秒内开通，到期日往后加 31 天；A 那边同步变化；`orders` 那条 `delivered`，`env` 是 0。
4. 现网下 A（安卓）也买一次月度会员。
   → 和第一节第 4 步一样；用的是微信支付，交易订单里的环境是「现网」。

## 三、平台侧异常扣款的处理流程

这一节测的是「付了钱但没开通」和「平台要求退回的钱」两种异常，在我们这边怎么处理、会员天数会不会算错。**不是测用户自己申请退款**：协议写的是虚拟商品不退款，小程序里也没有退款入口。

### 3.1 付了款没开通（掉单）

1. A 买月度会员，付款成功的一瞬间直接把小程序划掉（不等「开通成功」）。
2. **现网**：等一分钟再打开会员页。
   → 已经开通（靠微信的发货推送）；`api` 日志里有一次 `xpay_goods_deliver_notify`；天数只加了一次。
3. **沙箱**（沙箱不发发货推送）：打开会员页。
   → 还没开通，`orders` 那条停在 `pending`，交易订单里显示已支付。这就是「付了款没开通」，按下面补开通。
4. 补开通的做法（用户来反馈时也照这个做）：
   1. 交易订单里按时间、金额找到这笔，确认是「已支付」，记下商户单号（`V` 开头那串）。
   2. `orders` 里按 `outTradeNo` 找到同一条，记下 `openid`、`productId`。
   3. 云开发控制台 → 云函数 `api` → 云端测试，事件填：
      ```json
      { "Event": "xpay_goods_deliver_notify", "OutTradeNo": "商户单号", "OpenId": "openid", "GoodsInfo": { "ProductId": "vip_month" } }
      ```
   → 返回 `{"ErrCode":0,"ErrMsg":"Success"}`；会员页到期日加 31 天；`orders` 变成 `delivered`。
5. 同一个事件再测一次。
   → 仍然返回 `ErrCode 0`，到期日**不再增加**。
6. 拿第一节第 3 步那条取消支付的 `pending` 订单，照第 4 步测一次。
   → 返回 `{"ErrCode":1,"ErrMsg":"not paid"}`，会员不变。说明没付钱的订单补不出会员，伪造推送也没用。

**不要**手动改 `households` 的 `vip.until` 来补天数：之后再来的推送会按订单再算一遍，手改的天数会对不上（2026-10-27 出过一次）。

### 3.2 平台要求退回的钱

只有微信或苹果判定需要退回的（例如平台确认的重复扣款、系统故障、投诉裁定），才在虚拟支付后台操作退款。测试时用第一节、第二节买的月度会员订单。

1. 公众平台 → 虚拟支付 → 交易订单，找到 A 的一笔 9 元订单，全额退款。
   → 几秒后会员页到期日往回减 31 天（只减这一单，别的订单加的天数不动）；`orders` 那条有 `refunded: 900`；`api` 日志里有一次 `xpay_refund_notify`。
2. 用云端测试把退款推送再发一次：
   ```json
   { "Event": "xpay_refund_notify", "MchOrderId": "商户单号", "OpenId": "openid", "RetCode": 0 }
   ```
   → 返回 `ErrCode 0`，到期日**不再减少**。
3. 拿一笔**没退过款**的已开通订单，用同样的事件测一次。
   → 到期日不变（云端会向微信查单，查到没退钱就不扣），说明伪造退款推送扣不掉会员。
4. 把测试买的其余 9 元订单也在后台退掉。
   → 每退一笔，到期日减 31 天；全部退完后会员页回到「还不是会员」（扣完早于现在就等于结束）。
5. iPhone（苹果代收）的订单：后台不能退，用户只能找苹果申请，这一项没法自己测。苹果退款后如果收到 `xpay_refund_notify`，会和上面一样自动扣天数；没收到推送就不会扣，到时看 `api` 日志。

## 四、两人共用

先让小家重新有会员（买一次月度会员）。

1. B 续费一次月度会员。
   → 到期日接在 A 买的之后再加 31 天，两人看到的一样。
2. 用两人都在的测试小家，B：设置 → 退出小家。
   → 页面写明「会员还剩 N 天，全部留给（A 的称呼）。新小家没有会员。」；退出后 B 的新小家「还不是会员」；A 的小家到期日不变。
3. A（只剩自己）：设置 → 退出小家。
   → 页面写明「会员还剩 N 天，退出后会一起作废。」；确认后回到「创建 / 加入」，重新创建的小家没有会员。
4. 1.8.3 合并后再测注销账号：两人时注销，会员留给对方；只剩自己时注销，会员作废。

## 五、账单导入

截图识别次数按小家每天算，测之前看一下当天已经用了多少。

1. **非会员截图记账**：A 连续识别截图到第 6 张。
   → 前 5 张正常；第 6 张提示当天次数用完，多一句「开通会员每天可以识别 100 张。」和「看看会员」，点了进会员页。
2. **会员截图记账**：开通后再识别。
   → 能超过 5 张；识别出的每一笔先列出来逐笔确认，确认后才保存。
3. **微信账单文件**（A）：微信「我 → 服务 → 钱包 → 账单 → … → 下载账单 → 用于个人对账」，把 Excel 发到文件传输助手；记账页「导入账单 → 微信账单文件」选它。
   → 几秒后进确认列表，顶部写读出多少笔、跳过多少；部分退款的那笔是净额、备注带「已退¥…」；全额退款的不在列表里；之前截图导过的显示「已导入过」。保存后再导一次同一个文件，全部是「已导入过」。不占截图识别次数。
4. **支付宝账单文件**（B）：支付宝「账单 → … → 开具交易流水证明 → 用于个人对账」拿到 CSV，发到文件传输助手；「导入账单 → 支付宝账单文件」选它。
   → 进确认列表；外卖显示店名；退过款的是净额；保存后再导一次全部是「已导入过」。
5. **两人之间的转账**：两人在设置里填好「我的微信名字」，再导入含互相转账的账单。
   → 这些转账显示「你们俩之间的转账，默认不记」，默认不勾。
6. **同步**：A 导入保存后，B 打开记账页。
   → B 能看到 A 导入的账，付款人是 A。

## 六、测完收尾

- 测试买的订单都已在第三节退回，`orders` 里每一条要么 `refunded` 等于价格，要么是没付钱的 `pending`。
- 交易订单里没有遗漏没退的测试订单（iPhone 那笔除外，只能找苹果）。
- 测试小家清空或留着都行，别和正式在用的小家混在一起。
