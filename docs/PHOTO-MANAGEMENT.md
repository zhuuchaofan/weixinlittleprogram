# 主人工作台与照片管理

## 本次上线前只需配置一次

1. 云开发 → 数据库，新建 `photo_content` 集合。安全规则设为 `{ "read": false, "write": false }`。客户端通过云函数访问，不开放数据库直读。
2. 更新部署 `cloudfunctions/weddingApi`，选择云端安装依赖。保留已有 `ADMIN_OPENIDS` 环境变量（多个管理员 OpenID 以英文逗号分隔）。不需要新密钥或 AppSecret。
3. 云存储使用“所有用户可读”、客户端不可写的规则。管理员上传通过已鉴权的云函数完成，不要为了上传开放所有用户写权限。原有图片文件和登记记录保持不动。
4. 重新编译、预览小程序。管理员进入首页后看到主人工作台；普通访客没有此入口。请求失败时入口也隐藏。云函数未更新时同样隐藏，先完成步骤 2。
5. 管理员进入工作台 → 照片管理。首次会带入代码中现有照片安排，先保存草稿，再更新展示。
6. 用另一个非管理员微信验证入口隐藏、相册正常显示。新版小程序仍需主人自行上传审核，本次没有代为发布。

## 日常如何使用

- 从手机添加照片：一次一张，自动压缩，支持 JPG/PNG。上传的是展示副本，不覆盖手机原图。压缩后仍超过约 500 KB 会提示重新选择；原始高清照片仍可通过既有配置/控制台维护。
- 每条照片安排选择用途：婚纱照相册、首页封面、故事照片、球球、布丁。最多 60 条安排。
- 首页只有一张封面。选新封面时，原封面条目转入相册，可再移除。照片横竖比例由图片加载尺寸适配，点图看大图。
- “同时用于其他位置”复用已上传文件，不重复占用云存储。为新增条目选择其他用途即可。
- “前移 / 后移”改变同一用途的展示次序，说明最多 80 字。故事照片放入当前第一段故事，故事文字仍在本地配置维护。
- “保存草稿”不改变亲友页面；“更新展示”确认后生效。亲友重新进入首页、照片册或故事页获取最新安排。
- 离开前记得保存。未保存的编辑不会自动保留；多位管理员请避免同时编辑，最后保存的版本生效。
- “移除”只从展示安排移除，不删除云文件。误删展示条目仍可通过文件 ID 恢复；不再需要的文件由主人在云存储控制台确认后清理，包括未保存草稿的上传文件。

## 数据与权限

`photo_content/draft` 存草稿，`photo_content/published` 存已展示安排。两者包含照片 ID、说明、用途、比例和文件 ID，没有管理员名单或宾客数据。

公开读接口只返回 published。getAccess 仅返回 isAdmin，服务端从 getWXContext 读取身份，与 ADMIN_OPENIDS 比较；草稿读取、上传、保存、发布每次都校验。前端隐藏入口不是权限边界。

上传文件在公开可读存储中：草稿不会出现在访客页面，但已知文件链接的人仍可读取，不适合私密照片。没有永久删除或自动清理功能。

未有云端发布内容或首次读取失败时保留本地配置；已打开页面读取失败则保留当前显示。成功读取空数组表示清空安排，不恢复旧照片。mock 模式保存至本机，不能同步到亲友；需 mockAdminEnabled 开启才显示管理入口。

## 本地检查与真机验收

已加入服务端测试：伪造身份拒绝、写入前鉴权、草稿隔离、发布顺序、空列表、非法文件/多封面/重复编号。类型、lint、原生 WXML/WXSS 编译及浏览器布局回归见项目检查命令。

仍须主人部署后真机核验：管理员/访客两账号、手机选图和压缩上传、图片临时地址、大图、断网重试、保存草稿后访客不变化、更新展示后访客变化。浏览器辅助预览不能证明真实云上传成功。


## 照片管理界面整理

沿用暖米白、宋体标题与酒红色强调，以编号和细分隔线组织照片。管理页使用固定横向画框、完整比例预览；不改变访客页照片比例。说明、用途、排序和复用操作分层排列，保存草稿与更新展示采用吸顶工具栏。用途选择器默认定位当前用途。未修改云端权限与发布流程。
