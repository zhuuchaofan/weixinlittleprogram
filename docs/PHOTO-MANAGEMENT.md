# 主人工作台与照片管理

## 本次上线前只需配置一次

1. 云开发 → 数据库，新建 `photo_content` 集合。安全规则设为 `{ "read": false, "write": false }`。客户端通过云函数访问，不开放数据库直读。
2. 更新部署 `cloudfunctions/weddingApi`，选择云端安装依赖。保留已有 `ADMIN_OPENIDS` 环境变量（多个管理员 OpenID 以英文逗号分隔）。不需要新密钥或 AppSecret。
3. 云存储使用“所有用户可读”、客户端不可写的规则。管理员上传通过已鉴权的云函数完成，不要为了上传开放所有用户写权限。原有图片文件和登记记录保持不动。
4. 重新编译、预览小程序。管理员进入首页后看到主人工作台；普通访客没有此入口。请求失败时入口也隐藏。云函数未更新时同样隐藏，先完成步骤 2。
5. 管理员进入工作台 → 照片管理。首次会带入代码中现有照片安排，先保存草稿，再更新展示。
6. 用另一个非管理员微信验证入口隐藏、相册正常显示。新版小程序仍需主人自行上传审核，本次没有代为发布。

## 日常如何使用

- 从手机添加照片：一次一张，自动压缩，支持 JPG/PNG。上传的是展示副本，不覆盖手机原图。完整上传请求超过应用保守上限 180,000 字符时会继续压缩，仍超限则提示导入云文件；原始高清照片仍可通过既有配置/控制台维护。
- 每条照片安排选择用途：婚纱照相册、首页封面、故事照片、球球、布丁。最多 60 条安排。
- 首页只有一张封面。选新封面时，原封面条目转入相册，可再移除。照片横竖比例由图片加载尺寸适配，点图看大图。
- “同时用于其他位置”复用已上传文件，不重复占用云存储。为新增条目选择其他用途即可。
- “前移 / 后移”改变同一用途的展示次序，说明最多 80 字。故事照片放入当前第一段故事，故事文字仍在本地配置维护。
- “保存草稿”不改变亲友页面；“更新展示”确认后生效。亲友重新进入首页、照片册或故事页获取最新安排。
- 离开前记得保存。未保存的编辑不会自动保留；多位管理员请避免同时编辑，最后保存的版本生效。
- “移除”只从展示安排移除，不删除云文件。要永久删除手机上传的照片：先复制该照片 File ID，移除展示后保存草稿并更新展示，再打开“清理不再使用的云端照片”检查引用数；草稿和已展示引用均为 0 时才能二次确认永久删除。误删展示条目仍可通过 File ID 恢复。

## 数据与权限

`photo_content/draft` 存草稿，`photo_content/published` 存已展示安排。两者包含照片 ID、说明、用途、比例和文件 ID，没有管理员名单或宾客数据。

公开读接口只返回 published。getAccess 仅返回 isAdmin，服务端从 getWXContext 读取身份，与 ADMIN_OPENIDS 比较；草稿读取、上传、保存、发布每次都校验。前端隐藏入口不是权限边界。

上传文件在公开可读存储中：草稿不会出现在访客页面，但已知文件链接的人仍可读取，不适合私密照片。管理页可永久删除仅由小程序上传的 `wedding/managed/` JPG/PNG；服务器会检查草稿和已发布内容均未引用后才删除。手动上传到 `wedding/original/` 的原图继续在云开发控制台维护，避免误删。

未有云端发布内容或首次读取失败时保留本地配置；已打开页面读取失败则保留当前显示。成功读取空数组表示清空安排，不恢复旧照片。mock 模式保存至本机，不能同步到亲友；需 mockAdminEnabled 开启才显示管理入口。

## 本地检查与真机验收

已加入服务端测试：伪造身份拒绝、写入前鉴权、草稿隔离、发布顺序、空列表、非法文件/多封面/重复编号。类型、lint、原生 WXML/WXSS 编译及浏览器布局回归见项目检查命令。

仍须主人部署后真机核验：管理员/访客两账号、手机选图和压缩上传、图片临时地址、大图、断网重试、保存草稿后访客不变化、更新展示后访客变化。浏览器辅助预览不能证明真实云上传成功。

## 照片管理界面整理

沿用暖米白、宋体标题与酒红色强调，以编号和细分隔线组织照片。管理页使用固定横向画框、完整比例预览；不改变访客页照片比例。说明、用途、排序和复用操作分层排列，保存草稿与更新展示采用吸顶工具栏。用途选择器默认定位当前用途。未修改云端权限与发布流程。

## 已上传文件未出现在照片管理中

云存储文件与照片展示安排是两份数据；文件存在不能证明草稿已保存。新版手机上传后自动保存当前草稿（不自动发布）。保存失败时明确提示，请留在页面重试。历史遗留文件可点击“已上传过？用文件 ID 导入”，粘贴完整 cloud:// 地址，加入并保存草稿。导入不重新上传文件，不预先证明文件可访问；请检查预览，选择球球/布丁等用途，再更新展示。导入时会同时保存当前其他编辑。

首页猫咪区域按球球、布丁分别保留占位，并使用与婚纱照相册一致的双列瀑布流、画框和大图预览：某只猫未发布照片时显示它的占位，发布后替换为该猫的照片；清空该猫照片后恢复占位，不影响另一只猫。占位不进入大图预览。

## 上传时提示云端暂时不可用

这表示 callFunction 调用未成功返回，不能仅凭提示判断是手机网络故障，也不能确认文件一定没写入。前端现在清除残留“正在上传”提示，并在可用时显示数值错误码，识别超时/调用拒绝；不展示原始错误内容或请求照片数据。

请到云开发 → 云函数 → weddingApi → 调用日志，按失败时间检查错误和耗时。如果是执行超时，到函数配置检查超时时间，过短时可调到 20 秒再保存并验证。配置修改与小程序代码上传是不同操作，不必删除云函数或改变管理员名单。若日志显示调用成功，继续核对客户端错误码及响应；若无记录，核对环境、调用权限与网络。

官方配置说明：https://docs.cloudbase.net/cloud-function/function-configuration/config 。本次没有读取线上日志，超时仅为待验证方向。

通用错误码 -1 无法单独定位原因。新版上传失败时提供“复制上传诊断详情”：包含时间、操作名、请求字符数、错误码与经过地址/长数据脱敏的 SDK 错误文字，不含照片请求载荷。用于区分传输大小、网络和平台拒绝，未确认原因前不扩大存储写权限。

2026-09-17 真机诊断已确认：uploadPhoto 请求 430,140 字符被调用链路以 data exceed max size 拒绝（errCode -1），不是已确认的执行超时。已改为逐级压缩展示副本，并按完整请求（含 JSON 包装）180,000 字符限制在发送前校验；这是应用保守阈值，不声明为平台统一上限。原图不改动，小图不放大。若希望保留高清，仍可控制台上传后导入 File ID。本修复仅需重新编译预览，无需云函数部署；实际 iPhone 上传需真机复核。

## 访客页照片刷新（2026-09-17）

首页、照片册和故事页每次显示时都会读取已发布安排，但只有照片的顺序、用途、说明、File ID 或比例确实变化时，才会更新页面。点开大图再返回时，相同照片不会重新进入“照片正在赶来”。

首次打开首页先显示简洁留白，等读取结果确认后才显示照片：没有已发布记录或暂时无法读取时使用本地正式配置；已打开页面后来读取失败时保留已经看到的照片。成功读取空数组表示主人主动清空展示，不恢复本地旧照片。球球和布丁仍分别保留各自占位。

主人更新展示后，旧缩略图会保留到新图加载成功才切换；新图加载失败时继续保留旧图。首次加载本身失败仍会显示“重新加载”，该操作只清除这一张 File ID 的临时链接缓存，再重新请求，不影响其他照片。

## 隐私授权与安全清理（提审整改版）

- 管理员点“从手机添加照片”时，小程序先请求微信原生隐私授权；拒绝或取消后不会打开相册、不会上传文件。上线前须在公众平台隐私保护指引和体验版指引中如实声明管理员主动从相册选择照片。
- “清理不再使用的云端照片”不会列出云存储文件。管理员必须主动粘贴完整 File ID；云函数仅接受 `wedding/managed/` 下由本小程序上传的 JPG/PNG，并在删除前后端都确认它没有被 `draft` 或 `published` 引用。
- 云函数更新后才有 `inspectManagedPhotoFile` 和 `deleteManagedPhotoFile`。部署后以管理员、访客两账号复核：访客直接调用这两个 action 必须被拒绝；仍被引用的照片必须无法删除。
