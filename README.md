# 小家

超凡和佳益两个人共用的微信小程序：记账、清单、吃啥、周末、纪念。由答谢宴小程序改造而来，方案见 [docs/PLAN.md](docs/PLAN.md)，阶段 0 调查与决定见 [docs/STAGE-0-REPORT.md](docs/STAGE-0-REPORT.md)。

只通过体验版给两个人使用，不对外发布，不做支付。

## 当前进度

- 路线规划与长期目标见 [docs/ROADMAP.md](docs/ROADMAP.md)。
- 阶段 1（已验收）：5 个 tab、创建 / 用邀请码加入小家、「纪念」页成员与设置、答谢宴登记与祝福只读归档。
- 阶段 2：
  - 记账（M1–M3）：记一笔（人民币，最多两位小数，以「分」为整数存储；9 个分类、日期、付款人、分摊方式）、按月汇总与结算建议、记为已结算（删除结算记录即撤销）、编辑与删除。
  - 清单（T1–T2）：购物 / 待办 / 家务，指派给某人或一起，勾选、编辑、删除。
  - 导出（G2）：「纪念」→「复制全部数据」，复制为带版本号的 JSON。
- 阶段 3：
  - 吃啥（F1）：菜单增删改（在家做 / 外食 / 外卖），按类型筛选后随机抽一个，尽量不连续抽到同一道。菜单里的每一条分「菜品」和「店家」两类：顶部先选「全部 / 菜品 / 店家」，再选标签；店家只有外食、外卖，没有「在家做」；没有分类的旧记录算菜品。
  - 周末（W1）：收藏想去的地方（地点、理由、计划），可编辑删除。
  - 纪念日（D1）：在「纪念」页，倒数天数，可每年重复（显示第几年）；不重复且已过的显示「已经 N 天」。
  - AI 占位：云函数 `ai-suggest` 始终返回 `{ disabled: true, items: [] }`，页面据此隐藏「让 AI 推荐」与周末条件筛选。
- 阶段 4A（稳固）：结算防重复、读取超限明确报错、编辑页按 id 取单条、前后端共用 `shared/contract.json`、真实 SDK 测试。
- 阶段 4B：
  - 分类统计（M4）：记账页「按分类」卡片，显示本月共同支出各分类的金额与占比（与共同支出同口径，不含结算和「自己的」）。
  - 自定义分摊比例（M5）：记一笔的「怎么分」新增「按比例」，填付款人自己承担的百分比（整数 0–100，6:4 填 60），页面实时显示两人各承担多少；明细显示「按比例 60:40」（付款人在前）。
- 只记账：设置里的「两人分摊与结算」默认关闭。关闭时记账页顶部为「本月支出」，「按分类」与它同口径（所有支出，含「自己的」，不含结算记录和收入），不显示结算建议、「记为已结算」和「怎么分」；打开后恢复共同支出与结算。
- 截图记账：记账页「截图记账」选微信 / 支付宝账单列表截图，千问 AI 平台识别、查重，确认后导入（全算自己的）。部署见 DEPLOYMENT.md。
- 导出包含记账、清单、菜单、周末收藏、纪念日；入口在「纪念」页右上角的设置（成员、称呼与城市、数据备份）。
- 底部 tab 带图标，选中时图标填充为主色（`miniprogram/images/`，由 Pillow 生成）。

### 方案之外的约定

- 纪念日 2 月 29 日在平年按 2 月 28 日计算。
- `ai-suggest` 额外接受 `probe: true`：只回答是否可用、不生成内容，小程序进入「吃啥」「周末」时用它决定是否显示 AI 按钮。函数未部署或调用失败时同样视为不可用。
- 周末的「条件筛选」（时长、心情、预算、交通）是给 AI 的输入，AI 不可用时与按钮一起隐藏。

### 记账规则的落地细节

- 金额单位为「分」：方案里的「整数日元」改为人民币后，仍按整数存储，结算金额四舍五入到分，|net| < 1 分视为已结清。
- 共同支出排除「结算」和「自己的」；结算建议的 net 也不计「自己的」，但计入结算记录，因此结算后 net 归零。
- 结算记录的日期：结算当月为今天，结算过去月份时为该月最后一天，保证落在该月内。
- 分类「食费」已改名为「吃饭」：数据库里的旧记录不迁移，读出、统计、导出时自动当作「吃饭」，保存时存成新名称；`shared/contract.json` 的 `categoryAliases` 记录这类改名。
- 两人对所有账目权限相同，谁都能改、能删；改过的账目记下最后一次修改的人和时间（`editedBy`、`editedAt`，对外只返回角色）。明细里对方改过的账目显示「某某改过」，账目编辑页显示「某某修改于 …」，导出里带 `editedAt`、`editedByRole`。删除不留记录。
- 按比例分摊的 credit = round(金额 × (100 − 比例) / 100)，四舍五入到分（恰好半分进位）；比例 0 等同「全算对方」，100 不产生欠款但仍计入共同支出。
- 结算记录不能编辑，只能删除（即撤销结算）。
- 结算记录的 `_id` 是确定的：`settle_<月份>_<小家 id 与该月全部记录 id 排序后的 SHA-256 前 24 位>`。两人同时结算时只有一条插入成功，另一人收到「本月已经结清了」并刷新；撤销后账目回到原样，可用同一 `_id` 重新结算。

## 架构

```
小程序（TypeScript，开发者工具 typescript 编译插件）
   │ wx.cloud.callFunction({ name: 'api' })
   ▼
云函数 api：所有读写的唯一入口，按 openid 校验 household 成员
云函数 ai-suggest：AI 接口占位，暂时总是 disabled
   ▼
CloudBase 数据库：所有集合禁止客户端直接读写
```

- `cloudfunctions/api/router.js`：action 分发；`household.js`：小家；`expenses.js` + `ledger.js`：记账与结算规则；`todos.js`：清单；`export.js`：导出；`collections.js` + `crud.js`：吃啥、周末、纪念日；`anniversary.js`：纪念日倒数；`archive.js`：答谢宴归档只读。
- 每条业务记录都带 `householdId`、`ts`、`by`（openid），读写都限定在本小家内。
- 返回给小程序的数据不包含 openid。
- 日期按中国时区（UTC+8）展示。
- 分类、标签、字段长度等前后端共用的规则只在 `shared/contract.json` 写一份，副本由 `npm run contract` 生成（`cloudfunctions/api/contract.json`、`miniprogram/config/contract.ts`），测试会发现漏同步。
- 日常读取（列表、按月账目）超过 2000 条时返回 `TOO_MANY`，不会静默少数据；导出按 `count()` 读完整，结果带各集合 `counts`。

## 使用

1. 在微信开发者工具打开 `D:\chaofan\weixinlittleprogram`（不要只打开 `miniprogram`）。
2. `miniprogram/config/local.ts` 填写云环境 ID（干净副本先运行 `npm ci`、`npm run setup`）。

## 常用命令

```powershell
npm run setup          # 干净副本：生成本地配置、同步契约、安装云函数依赖（SDK 测试需要）
npm run contract       # 改了 shared/contract.json 之后运行，同步到云函数与小程序
npm run check          # TypeScript、ESLint、自动测试
npm run check:native   # 本机微信 WXML/WXSS 编译器检查（需要 Windows 上的开发者工具）
```
